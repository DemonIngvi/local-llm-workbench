# Архитектура и решения

## Целевая схема
`LibreChat → OpenAI-compatible adapter/orchestrator → [OpenCode | DeepSeek Harness] → LiteLLM → LM Studio/llmster`.
Альтернативный прямой маршрут чата: `LibreChat → LiteLLM → LM Studio/llmster`. На Windows модельный сервер работает на Windows, Docker — в Docker Desktop/WSL; на Linux модельный сервер на хосте. Связность пересекает границы namespace и должна проверяться отдельно.

## Границы
Текущая реализация содержит только прямой маршрут. Custom endpoint LibreChat не является универсальным протоколом запуска внешнего агента. Будущему адаптеру нужны собственный API chat completions, соответствие streaming и модельной выборки, маршрутизация в контролируемые отдельные контейнеры, управление сессией, сохранение контекста и обработка ошибок. Возможен выбор harness через отдельные endpoint; смена endpoint сама по себе не переносит состояние. Общий task manifest, история handoff и состояние workspace — явный контракт, ещё не реализованный.

Агент запускается от непривилегированного пользователя в выделенном контейнере; workspace монтируется только после явного выбора, сеть ограничивается, Docker socket и секреты других сервисов не предоставляются, запись сериализуется per workspace. Контейнер не гарантирует надёжную изоляцию: нужны усиление, подтверждение опасных действий, стратегия отката и аудит. Доступ к LiteLLM через отдельный ограниченный ключ — задача следующего этапа. Защита от prompt injection не гарантируется.

## Решения и риски
LM Studio на Linux или официальный llmster вместо стороннего сервера; `/v1/models` для единого формата. LiteLLM отвечает за настройки подключения. Список обновляется вручную; JSON-конфигурация совместима с YAML. MongoDB и Meilisearch — зависимости LibreChat. В текущем compose нет RAG. Секреты создаются локально, порты публикуются на loopback. Образы LibreChat и LiteLLM пока не зафиксированы по digest; требуется закрепление и compatibility test. DeepSeek Harness developer preview, API меняется; надо проверить реальный поддерживаемый способ подключения к совместимому провайдеру и интеграции агента до реализации. Модель может не поддерживать tools.
