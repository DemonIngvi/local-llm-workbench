# Подготовка интеграции OpenCode V2

После успешного `start` или `refresh` обнаруженные модели также записываются в `generated/opencode.json`: это конфигурация экспериментального V2 provider `local-litellm`, который использует `http://litellm:4000/v1` и переменную окружения `LITELLM_MASTER_KEY`. Адрес применим **только внутри Docker-сети Compose**, где резолвится имя `litellm`. Это подготовка конфигурации: контейнер OpenCode пока не добавлен, файл автоматически никуда не монтируется, подключение реально не проверено.

`scripts/opencode_client.py` содержит экспериментальный клиент V2 API: `create_session`, `prompt`, `wait`, `messages`. `scripts/orchestrator.py` связывает его с захваченной задачей: состояние вызовов записывается в SQLite до отправки запроса; при сетевом сбое повтор и снятие блокировки запрещены до ручной проверки. Это библиотечный прототип без CLI или сервиса LibreChat; он не запускает ни OpenCode, ни LM Studio. Проверка выполнена с локальным HTTP-моком и моками клиента, а не настоящим сервером. API экспериментальный, версия сервера пока не зафиксирована. Требуются отдельные integration-тесты с выбранной версией и подключением к LiteLLM.

При создании запуска сохраняется снимок названия задачи и последней сводки handoff. При первом `submit` они отправляются вместе с запросом как JSON-контекст, следующие сообщения той же сессии их не дублируют. Это перенос только явно записанной сводки, а не внутренней истории DeepSeek. Контекст является недоверенными данными и не защищает от prompt injection. Для запусков, созданных до добавления этой схемы, отправка блокируется — после проверки завершите старый запуск и создайте новый.

В создаваемую сессию и пример конфигурации намеренно добавлено правило `deny` для всех действий — это не рабочий кодовый агент. Правила OpenCode могут переопределяться правилами агента; изоляция процесса и проверка эффективной политики по-прежнему обязательны. Не запускайте этот клиент против сервера с доступом к важным данным без изучения его конфигурации и разрешений. Клиент не обрабатывает запросы подтверждения, отмену и поток событий; `wait` не отменяет выполнение при тайм-ауте. Не передавайте в него произвольные URL или токены недоверенному коду. Запуск только в защищённой среде, на доверенном endpoint.

Дальнейшая работа: контейнер, фиксированная версия OpenCode и проверка соответствия V2 API; отдельная учётная запись LiteLLM с ограниченным ключом вместо master key; orchestrator, который связывает сессии с задачей и блокировками; мост к LibreChat, передача событий и обработка разрешений. До этого UI-переключения harness нет.

Состояния `creating`, `submitting`, `running`, `waiting`, `uncertain` запрещают освобождение задачи. `reconcile` доступен только для `uncertain` и лишь фиксирует **утверждение оператора**, что процесс и все отправленные запросы действительно завершены; сам сервер он не проверяет и не останавливает. Применять только после независимой проверки, иначе возможно одновременное выполнение. После аварии клиента промежуточное состояние может застрять; автоматическое или административное восстановление пока не реализовано. `idle` подтверждает только ответ API `wait`, но не успех выполнения; результат и сообщения нужно проверить вручную. Журнал не хранит текст промпта, но база хранит адрес сервера, пути и идентификаторы сессий. Прототип не проверяет, что серверный путь соответствует локальному workspace, и не защищает от процессов в обход реестра, вложенных или одинаковых путей между Windows/WSL; его нельзя использовать как гарантию изоляции или production-блокировку.
